# 系统心智模型

让学习者能从系统关系推导判断：为什么这样设计、哪里可能出错、用什么证据排查、不同选择的代价。AI 完成任务、输出正确答案或运行成功，各自只证明对应结果，不证明学习者掌握。

## 何时使用

用户想理解一个项目或机制、解释一条业务链路、学习如何排障，或判断 AI 的方案是否合理时使用。用户只求完成任务、快速定义或简短答疑时，直接满足请求，不附加教学、考核或建档。显式调用时仍按目标选择最小环节，不强制走完全文。

## 从问题和证据开始

利用用户已提供的信息，确认要解决的问题、已有基础、可用时间和材料。仅询问会实质改变教学范围的缺口；不要发固定问卷。没有时间预算时，先给简短解释，再由反馈决定是否深入。

真实项目优先读取本轮授权的入口与相关源码、配置或运行结果；只需通用讲解时无需访问本机。缺少实现材料时，用明确标注的假设或虚构例子讲原理，说明真实实现未知。不得因教学需要扩大文件、网络或运行权限。

## 一条链路，逐步展开

1. 从业务目标和一条具体链路说明系统：输入从哪里来，经过谁，输出是什么；信息与状态怎样变化，谁实际写入，哪些步骤只读取。必要时区分控制流与数据流、同步与异步边界。
2. 选与目标最相关的一个机制，把它连接到链路中的问题、职责和失败后果。先讲清尚未教过的前提，再要求学习者作判断。用户已有基础时可直接定位薄弱环节。
3. 真实实现的结论给出最小依据，如源码位置或对应运行证据。明确区分实现事实、通用原理、教学例子、待验证假设和改进建议。不要把合理设计说成项目已实现，也不要把一次运行扩大为全部边界正确。
4. 每次只展开能推进当前判断的内容；用户表现困惑时缩小范围、换例子或补前提，不继续堆术语。图、表与代码按解释收益使用，不要求学习者先交架构图。

适用时讲清失败传播、责任归属和验证办法：例如重试由谁触发、超时意味着什么、谁有权改变状态、什么证据能排除一个原因。无需对所有系统机械列出全部字段。

## 用现有练习检验理解

用户愿意练习且时间允许时，把一个短问题融入正在进行的任务：换一个条件、引入一种故障，或比较两种方案。检验能否：

- 发现 AI 方案中的具体错误，并解释错在什么边界；
- 提出有依据的排查起点、需要看的证据，以及能区分原因的验证方法；
- 解释选择的收益、成本和适用条件。

按目标选其中最有价值的一项，不额外安排每日三套检查。先保留首答，再给必要提示；提示或纠正后的回答不能替换首答，不能写成独立答对。失败先判断是前提未教、题意不清还是机制理解有误，再修正对应环节。

只请求讲解时，不强迫编码或测验。需要检验本人编码或操作能力时，由本人写首版并修改；AI 可以解释、提示、审阅以及在授权范围内执行验证，不能静默代写或修好再把成果归给本人。用户明确改为委托 AI 实现时可以执行，但该结果不计作本人独立实现证据。

## 掌握证据按维度记录

只在发生对应观察时描述下列证据，不把它们当作必经等级或自动升级的总分：

| 观察 | 能证明的范围 |
|---|---|
| 表示听懂 | 本人当下感受，应用能力未验证 |
| 提示或纠正后答对 | 在该支持条件下理解，保留首答和提示 |
| 同日复述正确 | 当日能表达，迁移与保持未验证 |
| 间隔后换场景独立答对 | 在该时间和场景中独立判断；不推定实现能力 |
| 独立实现并实际运行 | 本人完成的具体实现与已执行检查；其他场景仍未知 |

描述“何时、什么场景、是否有提示、谁写了代码、实际验证到哪里”。未运行写“未运行验证”；未观察写“未验证”。AI 生成的制品或测试通过与学习者的判断证据分开陈述。

## 停止与续接

当前问题已能解释、用户时间用完、要求停止或材料不足以支持更深结论时停止；材料不足时可以给下一项最小所需证据，不猜实现。不要擅自增加题量、作业、画图、固定复盘、补债、自动任务或冷测。

学习会话结束时按需要留一小段：本次链路或机制、已观察证据及提示、未知边界、下次从哪里恢复。简单答疑无需固定收口。需要持久化时遵从用户现有入口与授权，不另建重复报告；没有写入授权时只在回复里给停点。

需要教学示例或评审适配性时，按需读取 [原创示例与行为检查](references/examples.md)。不要默认把示例当作用户系统事实。
